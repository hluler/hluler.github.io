AisiSlim Media Compressor

User-initiated foreground media processing

Package: com.aisifun.aisislim. The recording uses the internal 1.1.0/code2 build on Android16/API36. It demonstrates the actual on-device media flow; advertising and subscription acceptance are outside this video's scope.

Open/download the original recording

  1. The user opens Compress video and selects a synthetic60-second landscape clip with the Android document picker.
  2. The user selects Large File (1280×720), taps Generate, then confirms the file name to start processing.
  3. The app is sent to the background. The notification shade shows AisiSlim and changing processing progress (approximately16–40 seconds into the recording).
  4. The ongoing notification ends when processing completes. The resulting60-second H.264/AAC file was independently decoded in full.

All processing runs locally. No user media is uploaded. Notification permission was enabled on this dedicated test emulator. This recording contains only an original AI landscape and a synthetic test tone. It does not demonstrate a notification permission prompt or tapping the notification to return.

On API35+ the service uses mediaProcessing; API29–34 uses the dataSync local-transcoding fallback. Both service types are declared solely for this same user-initiated media queue, not for periodic/network transfers. API29–34 were not separately runtime-verified in this recording.

Deferring the task delays the output the user has explicitly requested. Interrupting it can prevent a complete file and requires the user to retry. The service stops when the queue finishes; users can cancel jobs in the queue. Privacy policy
